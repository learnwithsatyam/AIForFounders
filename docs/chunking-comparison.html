6Balanced splitting, per section replace One splitter for the whole book cuts a 400-word section into 350 plus a 50-word runt. Sizing per section gives two chunks of 200 instead. Note this is a change made against the library's default, not with it. 
def make_body_splitter(s: Settings) -> RecursiveCharacterTextSplitter:
    return RecursiveCharacterTextSplitter(
        chunk_size=s.target_words,
        chunk_overlap=s.overlap_words,
        length_function= lambda t: len(t.split()),
        separators=["\n\n", "\n", ". ", " ", ""]
    )
def split_section(doc: Document, s: Settings) -> list[Document]:
    """Even pieces, so there's no runt at the end."""
    words = len(doc.page_content.split())
    if words <= s.target_words * 1.15:
        return [doc]                      # close enough — leave it whole

    n = math.ceil(words / s.target_words)
    size = math.ceil(words / n)           # 400 words -> 2 x 200
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=size,
        chunk_overlap=0,                  # <- was s.overlap_words
        length_function= lambda t: len(t.split()),
        separators=["\n\n", "\n", ". ", " ", ""]
    )
    return splitter.split_documents([doc])

def classify(doc: Document) -> ChunkKind:
    m = doc.metadata
    name = str(m.get("subsection") or m.get("section") or "").lower().strip()
    file = str(m.get("source_file", ""))

    if name.endswith("in a nutshell"):    # <- suffix, not exact match
        return ChunkKind.RECAP
    if file.startswith("00c-contents"):
        return ChunkKind.TOC
    if file.startswith("15-glossary"):
        return ChunkKind.GLOSSARY
    return ChunkKind.PROSE

def merge_orphan_tails(chunks: list[Chunk], floor: int) -> list[Chunk]:
    """A short trailing chunk in the same section is a fragment,
    not an idea. Fold it back into its predecessor."""
    out: list[Chunk] = []
    for c in chunks:
        prev = out[-1] if out else None
        same_section = prev is not None and (
            (prev.chapter, prev.section) == (c.chapter, c.section)
        )
        if same_section and c.word_count < floor:
            out[-1] = prev.model_copy(update={
                "content": prev.content + "\n\n" + c.content
            })
            continue
        out.append(c)

    # ids must stay contiguous after merging
    return [c.model_copy(update={"id": i}) for i, c in enumerate(out)]

Why: the orphan chunks

Overlap was producing near-duplicate fragments — a section slightly over target split into a full chunk plus a runt that was mostly the overlap repeated. Five configurations, measured across your 13 chapter files. (The final patched script, run on the full 21-file folder, lands at 347 chunks with the same zero/zero result.) An orphan is a chunk under 150 words following another from the same section; a near-duplicate is one whose words are more than 70% contained in its predecessor.

Three changes, in order of impact 1. Overlap to zero. This alone eliminates every near-duplicate. Overlap exists to repair blind cuts; a recursive splitter cuts at paragraph and sentence boundaries, so there is nothing to repair. Fifty words of duplication per split bought nothing and cost you top-k slots. 2. Balanced sizing. Compute how many pieces a section needs and divide evenly. Halves the remaining orphans by construction. 3. Merge what's left. Eight stragglers survive at separator boundaries. A coherent 400-word chunk beats a 350 plus a fragment.

Why: classify instead of delete

An earlier version of this page said to delete the recaps and the table of contents. That was wrong on both counts, for the same reason: deletion is an irreversible decision made before you have any evidence.

ContentVerdictReasoning
Chapter recapskind = recap A recap's embedding is diffuse — it sits near the average of a chapter's topics, not near any one sharply. A focused question still retrieves the focused passage; the recap only wins on broad questions, which is exactly when you want it. About 14 chunks, 4% of the index.
Table of contentskind = toc "What's in this book?" is among the first things a reader asks. Keep the chunk — but the real fix is putting the chapter list in the system prompt, where it costs ~150 tokens, can never fail to retrieve, and gives the model a map of the whole book on every question.
Glossarykind = glossary Readers ask "what does X mean." Definitions are short and self-contained, which makes unusually good chunks.
Copyright, title page, about-the-authordropped Legal boilerplate that can only ever be a false positive.
Acknowledgmentsdropped Names real people — family and colleagues who did not agree to appear in a public chatbot. A privacy call before a retrieval one.
## Sourcesdropped Bibliographies retrieved as prose produce answers like "according to the book, https://fortune.com/…".
The principle Decide at retrieval time wherever you can. Drop at index time only for content that could never be a good answer to any question. Everything else gets a tag, because a tag is free and reversible while a deletion means re-indexing.

Reference: the chunking parameters

Every setting trades retrieval precision (small chunks match questions sharply) against answer completeness (large chunks carry whole arguments).

DecisionSettingReasoning
Primary splitmarkdown headings You already did the semantic chunking when you wrote the book — grouping related ideas under a heading is exactly what a chunker tries to infer. Your clean #/##/### hierarchy makes it nearly free.
Secondary split¶ → line → sentence → word Sections range from ~100 to ~2,000 words. Falling back through natural boundaries means a chunk almost never begins mid-sentence — a fragment reads as incoherent to both the embedding model and to Gemini.
Chunk size350 words ≈ 470 tokens Large enough to hold a claim plus its support; small enough that a top-8 retrieval stays specific. Anthropic's contextual-retrieval work used ~800-token chunks, so this sits in the same range.
Overlap0  (was 50) Overlap repairs blind cuts. Splitting on paragraph and sentence boundaries means the cuts aren't blind, so the 50 words bought nothing and produced near-duplicates competing for top-k slots.
Minimum size60 words Sub-60-word fragments are usually orphaned headings or list stubs. They embed to vague vectors that match everything weakly and nothing well.
Merge floor150 words Deliberately above min_words: a 100-word tail is long enough to survive the size filter but still too short to stand alone as an idea.
Embed ≠ storeembed_text vs content The highest-leverage line in the file. Mid-chapter text says "this approach fails at scale" without naming the approach — the heading two pages up did that. Prepending chapter and section before embedding restores the missing subject. Clean content still goes to Gemini.
Source filesfinal-manuscript/*.md Your book repo holds four copies of the manuscript. Indexing two versions means retrieval can hand Gemini contradictory drafts of the same passage, and you'd likely never notice.
None of this is settled until you measure it Everything above is informed prior, not proof. Write 30–40 questions real readers would ask, note which section genuinely answers each, then track how often the right section lands in your top-k. Change one variable, re-run, watch the number. An afternoon of that beats any amount of reading about chunking — including this page.

Reference: what the type layer buys you

Python gives you two independent layers. Annotations checked by pyright catch errors before you run; pydantic validates at runtime, when data crosses a boundary. TypeScript's types are erased at compile time — pydantic's are not.

ConstructWhereWhat it prevents
BaseSettingsclass Settings Config parsed and validated once at startup. A missing env var fails immediately with a clear message instead of a KeyError twenty lines into the run.
field_validatorbook_source_path Change 2. Relative paths anchor to backend/, and a typo'd path fails loudly instead of silently producing zero chunks.
frozen=Trueclass Chunk Chunks are immutable value objects, which is why the merge uses model_copy(update=...) to return a new one rather than mutating in place.
computed_fieldembed_text, word_count Derived from content, so they cannot drift out of sync. They still serialize into the JSONL via model_dump_json().
StrEnumChunkKind Serializes as a plain string into JSONL and Postgres, while pyright rejects any value outside the four.
Field(min_length=1)chapter, section, content An empty chunk raises at construction rather than entering your index and embedding to a meaningless vector.
